# 从高版本分支向低版本反向移植的流程

## 步骤

### 1. 更新依赖
根据 gradle.properties 中各注释链接查询当前 MC 版本的最新依赖版本：
- Fabric 相关（loader/loom/fabric-api/yarn）：https://fabricmc.net/develop
- 其他 Mod（malilib/minihud/litematica 等）：Modrinth
  可用的 API 查询格式：
  https://api.modrinth.com/v2/project/<slug>/version?game_versions=["<mc_version>"]

⚠️ 不要猜测版本号，必须根据链接实际查询。
⚠️ 更新完后 await 用户 runClient 验证。

### 2. migrateMappings
将源码映射迁移到目标映射系统：

```bash
# --mappings 指定目标(To)映射系统，来源(From)由 build.gradle 当前定义

# 从 Yarn → Mojang（本项目场景）：
./gradlew migrateMappings --mappings "net.minecraft:mappings:<MC版本>" --input src/client/java

# 从 Mojang → Yarn：
./gradlew migrateMappings --mappings "net.fabricmc:yarn:<yarn版本>:v2" --input src/client/java
```

输出在 `remappedSrc/`，复制覆盖到源码目录：
```bash
xcopy remappedSrc\* src\client\java\ /E /Y /Q
```

迁移后必须同步更新 build.gradle 和 gradle.properties：
1. `build.gradle`：`mappings "net.fabricmc:yarn:..."` → `mappings loom.officialMojangMappings()`
2. `gradle.properties`：移除 `yarn_mappings=...` 行

⚠️ 本项目使用 split sources（`splitEnvironmentSourceSets()`），必须加 `--input src/client/java`。
⚠️ 先提交 migrateMappings，再 runClient 验证。如有错误，修复后单独开一个新提交。
参考：https://fabricmc.net/wiki/tutorial:migratemappings

### 3. Synthetic merge
使用 `-s ours` 假合并跳过上一条分支的 migrateMappings 提交（**注意是具体 commit，不是整个分支**）：
```bash
git merge -s ours <上游分支的migrateMappings提交hash> -m "Synthetic merge ..."
```
作用：记录合并关系但不引入任何代码变更，后续 merge 以此为新共同祖先，只跳过 migrateMappings 这一个提交。

### 4. 合并上游最新
```bash
git merge <上游分支名>
```
将上游分支最新功能合并进来，处理冲突。
